# CINEMA 65 · v0.8.7 基础影调高光肩部／暗部趾部研究

日期：2026-10-27。状态：**研究版**；仅有桌面实图与 Java 回归；不对手机端运行及审美升级作结论；不替换 v0.8.2 稳定基线。

## 本轮解决的问题

上一轮模型预算和质量闸门只检查了新增模型引发的损伤；旧版 `FilmCore` 自身可能让局部原本不近白的像素进入近白，尤其明亮门框、逆光建筑。v0.8.7 单独新增 `ToneSafety.java`：在电影风格、冷暖分离、色域收敛之后，对**最终 8-bit sRGB**进行温和连续的安全肩部和趾部映射。这既不是额外的主体蒙版，也不是新的生成式增强。分离两种贡献：基础影调保护 vs ML 引导光线。

新 `FilmCore.Analysis` 公开 `setToneSafetyStrength(...,0/1)` 以实现严格同条件 A/B。默认研究值为 1，0 时恢复旧版输出（除新增函数之外不改变原有像素路径）；由 `MainActivity` 在诊断档案记录新旧死黑、死白、平均 RGB 差和受影响像素。

### 具体保护

- 高光肩部：仅当成片亮度 `Y>235/255` 且原始像素不是原本接近纯白时触发；颜色三通道同系数收敛，尽量保留本来的冷暖色相。纯白源像素不恢复不存在的细节。
- 暗部趾部：原图亮度 `Y>12/255` 并且成片 `Y<17/255` 时逐渐保护，避免把原本有可见纹理的阴影压成近黑；原本接近纯黑保持。
- 采用斜率连续的有界有理函数，避免硬剪裁色阶导致轮廓；不改变空间蒙版和具体塑光位置。
- 主要是防止**新增损伤**，不会对已有完全过曝的源图制造细节，也不是局部真实光照重建。

## 实图结果：9 张照片，3 种候选，27 组同条件对照

测试输入使用此前对话中已有的 7 张参考图截图，以及 2 张摩洛哥 JPEG。每张最长边 540px，按完全相同的主体/场景分析、候选编号、像素噪声与输出参数，只开关最后一道 ToneSafety；**此项独立评估使用纯算法，未用新的 U2NETP 蒙版重新引导**。

| 指标（27 组平均） | v0.8.6 | v0.8.7 | 解释 |
|---|---:|---:|---|
| 新增近白比例（原亮度 <238、出图 >=252） | 0.2772% | 0.0000% | 这套测试中近白新增已被抑制，不代表所有图 |
| 新增近黑比例（原亮度 >15、出图 <=3） | 0.0563% | 0.0000% | 避免可见暗部完全塌陷 |
| 近亮极值（原 15–235、出图 >=248） | 0.2749% | 0.0000% | 更稳健的亮部头部 |
| 差分“疑似新硬边”比例 | 0.00811% | 0.00805% | 没有增加此指标，但它只是启发式 |

两版的**平均绝对亮度差为 0.052/255**（按 27 组均值），最明显单组约 0.325/255，显示安全映射仅集中处理高风险极端值，而非大范围拉平底片。

具体可复核数据在 `research/tone_ab/audit.csv`。最高风险样本 `IMG_6062`（逆光摩洛哥街巷）的空间塑光候选里，新增近白从 **2.7484%** 降至 **0.0000%**，整幅平均额外绝对亮度改变约 **0.320/255**。修复主要聚焦天空/明亮建筑边界。注意，数据只能支持“降低特定数值损伤”，不能自动推出“画面更好看”。

视觉 A/B：`research/tone_ab/v087_tone_contact.jpg`，第四列差分为方便观察而增强 12 倍，**不代表真实视觉幅度**。部分参考图源是内嵌 Before/After 的拼接截图，所以不能把截图下半部的别人修图作品当成原始未编辑素材。

## 工程验证

- 新增 `ToneSafetyRegressionTest.java`: 单调、源白保留、旧版零增益精确回归、可见暗部、暖色相次序与跨分条输出一致。
- 保留此前约九组核心/融合/天空/边缘/风险回归；全部通过（Java 17）。
- 桌面随机 1100×770 帧的二次热身后试验：v0.8.6 约 170 ms，开启安全映射约 174 ms。仅是单次开发容器测量；不得推断手机、超大 JPEG 或 GPU 延迟。`ToneSafety.protect()` **不创建每像素 Java 对象**。
- Android 构建与运行态需要研究分支云端检查、最终在用户小米 17 Ultra 实测；不宣称现已完成手机端验证。

## 后续优先级

1. 在明确主体为高亮的图（如沙漏）检验“降低环境亮度、保留主体高亮”的完整曝光分配是否能提高视觉表达，不把保护系数强制降低来取得视觉变化。
2. 增加精细亮部纹理保留指标：在窗口、云、亮壁这些 ROI 比较局部纹理梯度，排除“安全曲线把局部亮度都压平”的情况；目前的新增死白指标不是纹理质量指标。
3. 用实机原始 80MP 文件测试峰值 RAM、导出一致性和耗时，避免像素安全功能掩盖大文件内存风险。
4. 等 U2NETP 的真实手机输出验证后，再和已验证的两个独立曝光预算共同进行审美 A/B 和盲评。

**研究边界：** 不发布正式新 APK；这轮实际修复基础影调极值，不把它误称为 U2NETP 或 NIMA 的功劳；不上传私人照片、蒙版与影像权重到公开 Git 仓库。

# CINEMA 65 v0.8.4 · 光照策略多假设 / 风险约束研究

**阶段：研发候选，非用户安装更新。** 2026-10-27。本轮基于 v0.8.3 独立研究分支。Android 机型实测及真实模型输出验收仍待完成。

## 结论先行

- 在七张用户提供的 Before/After 参考图和两张摩洛哥原片上，**旧方案切换不同风格时，空间亮点位置往往变化不大**。策略差异主要体现在全局色彩、对比度与塑光力度，而不是在选择不同受光目标。七张参考图的候选 0/1 平均绝对 RGB 差范围 3.48–15.19/255；这只是像素差异，**不是视觉质量分数**。
- 将主体 ROI 和相对深度**人工模拟**并输入真实 Java 渲染器后，三种模型引导方案能够呈现有区别的局部光影走向；合成回归中主体优先与空间优先平均 RGB 差 10.07/255，空间优先与沿用已有光线优先差 8.37/255。这项数据来自**合成图像/人工蒙版，绝不能声称真实模型已改善摄影作品**。
- 手工粗略主体标注在紫门场景把云层错误纳入主体，导致原研究方案产生明显不自然的亮斑。这证明单纯调强模型蒙版是不安全的。因此增加 **蓝天材质保护 + 已受光区域二次提亮限制**，并新增单元测试：亮蓝天和浅色云层不会因粗蒙版被提亮；深色紫色主体仍可获得合理增强。
- 候选评分器现在有空间相邻像素级的**新增硬边/边缘反转风险计量**，而非只看死黑死白与 NIMA。注意这只能发现特定像素瑕疵，不能保证没有光晕。
- 固定集 9 张原片 × 3 个候选的无模型基准中，走廊参考 `test_5366` 的空间塑光候选使 **11.01%** 的像素从原亮度 Y>15 降为 Y≤3（8-bit RGB 加权明度）；另外两候选为 3.59% 与 5.31%。这是实测的暗部损失风险，并不代表其余候选一定更优。
- 无可信模型时，**保留旧版像素结果**：两张摩洛哥原片 × 三种策略，v0.8.4 与 v0.8.3 逐像素完全一致（6/6）。

## 非人物主体分割：已验证为什么不能直接放行旧启发式

实验脚本 `region_probe.py` 用 SLIC + 颜色/空间/边界显著性，在参考照片中可发现路牌、墙上钟表及门框的若干局部；但是：

- 对沙漏只定位到沙子而非完整玻璃轮廓；
- 对紫色门可能找出门板和梯子，却没有完整、可信的独立门对象；
- 对走廊容易突出开门扇而非构图里真正的照明落点；
- 原始实验置信度在各图过度饱和（全部约 1），说明启发式分数**不能当语义概率**。

因此**没有将这个通用区域提案伪装成可靠的人工智能主体蒙版接入 Android**。接下来应验证真正的显著对象分割模型。预训练 U²-Net 的 LiteRT 发布已有现成大模型文件，但模型体积、输入输出格式与本机推理能力仍需实测，不能直接认定合适。

- 手工绘制的 ROI 与纵向梯度深度只是**假设输入**，用于评估“假如主体定位正确，策略会怎样工作”。任何这类图片均应标为模拟测试，不能标成真实 MiDaS/分割推理。

## 仍需攻克的任务（优先顺序）

1. **真实非人物主体模型**：选择并实测一个可离线运行的通用显著对象检测/分割预训练权重，验证静物、建筑、路牌、人物以外对象的轮廓；拒绝只有类别标签却没有轮廓的输出。
2. **真实模型 paired A/B**：用真实机器的主体和 MiDaS 深度蒙版，针对同一张图生成旧融合、新三策略、纯算法，记录局部曝光图以及人工偏好；实验过程不上传用户私人照片。
3. **假光保护**：除了硬边检测，还要通过平滑假光斑、主体边缘溢出、天空/云层扩散来评估，增加人工审阅的失败图库。
4. **图像质量**：添加真实人像回归样例；当前样本以风光、建筑、静物为主，不能声称人像无退步。
5. **工程性**：100 MP/80 MP 原分辨率内存峰值、方向与 EXIF/ICC 保留仍是独立问题；本阶段未修复。
